Архитектура программы (Двойная буферизация)

Вся логика строится на использовании двух матриц (буферов):

    grid — текущее состояние поля, которое прямо сейчас выводится на экран.

    next — буфер для следующего кадра. В него записываются результаты вычислений, чтобы обновление одних клеток не повлияло на расчет соседних в текущем кадре.

1. int main(void)

Это точка входа и главный контроллер игры. В этой версии она содержит «эталонную» инициализацию ncurses для работы после перенаправления stdin.

Детальный разбор работы:

    Инициализация: Создает две матрицы grid и next 25x80, заполняя их нулями. Устанавливает начальную скорость (speed = 100 мс).

    Чтение карты: Вызывает init_grid(grid), которая считывает начальный узор из файла (через stdin).

    Изоляция терминала (важнейший блок):

        FILE *tty = fopen("/dev/tty", "r"); — так как стандартный ввод (stdin) уже занят чтением файла с картой, мы напрямую открываем файл устройства текущего терминала /dev/tty для чтения нажатий с клавиатуры.

        SCREEN *term = newterm(NULL, stdout, tty); — вместо стандартного initscr() мы создаем новую сессию ncurses и явно говорим ей: «рисуй в stdout, а клавиатуру слушай из tty».

        set_term(term); — применяем созданные настройки.

    Настройки отрисовки (ncurses):

        noecho(); — прячет вводимые с клавиатуры символы (чтобы они не ломали графику).

        cbreak(); — отключает ожидание нажатия Enter (реакция на клавиши становится мгновенной).

        nodelay(stdscr, TRUE); — делает функцию getch() неблокирующей (если ничего не нажато, игра не останавливается, а летит дальше).

        curs_set(FALSE); — скрывает мигающий системный курсор.

    Игровой цикл (while (running)):

        Внутренний цикл while ((ch = getch()) != ERR) мгновенно считывает все нажатые клавиши из буфера.

        При нажатии 'a'/'A' переменная speed уменьшается (ускоряя игру, но не ниже 20).

        При нажатии 'z'/'Z' speed увеличивается (замедляя игру, максимум до 500).

        При нажатии пробела running становится 0, и цикл прерывается.

        Затем вызываются функции отрисовки (draw_grid), расчета (update_grid) и копирования (copy_grid).

        usleep(speed * 1000); — создает паузу (в микросекундах) между кадрами для визуализации.

    Завершение и очистка памяти:

        endwin(); — выходит из режима ncurses.

        delscreen(term); — освобождает память, выделенную под newterm.

        fclose(tty); — закрывает поток чтения клавиатуры.
        (Эти три строчки гарантируют, что программа пройдет тесты на утечки памяти).

2. static void init_grid(int grid[HEIGHT][WIDTH])

За что отвечает: Загрузка первого поколения клеток (seed) из перенаправленного файла (< map.txt).

Как работает:

    Посимвольно читает входящий поток с помощью getchar().

    Читает до тех пор, пока не встретит конец файла (EOF) или не заполнит 25 строк (r < HEIGHT).

    Если считывает перенос строки \n, переходит на следующую строку матрицы (r++) и обнуляет столбец (c = 0).

    Если считан символ '1', ставит в матрицу живую клетку (1). Если любой другой символ — мертвую (0). Шаг по столбцам (c++) происходит только если мы еще не вышли за границы ширины поля (WIDTH).

3. static void draw_grid(int grid[HEIGHT][WIDTH])

За что отвечает: Вывод массива grid на экран с помощью ASCII-графики.

Как работает:

    erase() — полностью стирает предыдущий кадр (работает быстрее и надежнее, чем clear()).

    Проходит вложенными циклами по всем 25 строкам и 80 столбцам.

    mvaddch(i, j, ...) — ставит курсор в позицию (строка i, столбец j) и рисует символ. Если в ячейке 1, рисуется ALIVE ('O'), если 0 — DEAD (' ').

    mvprintw(...) — выводит подсказку с управлением в левый нижний угол.

    refresh() — синхронизирует виртуальный экран ncurses с физическим экраном терминала, мгновенно отображая весь готовый кадр.

4. static int count_neighbors(int grid[HEIGHT][WIDTH], int y, int x)

За что отвечает: Подсчет живых соседей вокруг конкретной клетки с координатами (y, x).

Как работает:

    Переменные dy и dx от -1 до 1 позволяют заглянуть во все 8 соседних клеток (и в саму клетку-центр).

    if (dy == 0 && dx == 0) continue; — исключает саму клетку-центр из подсчета.

    Реализация тороидального массива:
    Формулы (y + dy + HEIGHT) % HEIGHT и (x + dx + WIDTH) % WIDTH «замыкают» поле в тор.
    Пример: Если мы смотрим соседа слева от нулевого столбца (x = 0, dx = -1), получается (0 - 1 + 80) % 80 = 79. То есть левым соседом для левого края автоматически становится крайний правый столбец.

    Прибавляет значение соседа к счетчику count и возвращает итог.

5. static void update_grid(int current[HEIGHT][WIDTH], int next[HEIGHT][WIDTH])

За что отвечает: Расчет следующего поколения по правилам игры Конвея.

Как работает:

    Проходится по каждой клетке текущего поля (current).

    Через count_neighbors узнает, сколько у нее соседей (результат в переменной n).

    Применяет правила:

        if (current[i][j] == 1): Клетка жива. Она останется жива (n == 2 || n == 3), иначе умирает (в массив next пишется 0).

        else: Клетка мертва. Она оживет, если соседей ровно три (n == 3).

6. static void copy_grid(int dest[HEIGHT][WIDTH], int src[HEIGHT][WIDTH])

За что отвечает: Синхронизация буферов.

Как работает:

    Построчно и постолбцово переносит все значения из вычисленного нового кадра (src / next) в текущий кадр (dest / grid).

    Именно после этой функции на следующем витке цикла while (running) экран нарисует уже обновленное состояние поля.
